# UI audit — 12 October 2026

The owner and users say the app is noisy, explains itself everywhere, wastes width
on every input, is inconsistent, and carries things nobody needs. This audit counts
all of it. The rules that stop it coming back are in `DESIGN.md`.

**How it was done.** Ten auditors each owned a slice of the app (nine read every
route and component in full, one drove the running app as admin, mentor and student
at 1440px and 390px and measured it). Every finding quotes the code. Each was
checked against the source: 484 matched the quoted line mechanically, and every
high-severity finding the script could not match (17), plus a random sample of the
rest, was opened by hand. Two did not hold and one recommendation was overruled;
they are struck through in the tables with the reason (S7-1, S7-10, S9-59). Every
cited line was re-blamed for the owner's decisions of the last three weeks.

**Prose has a delivery system.** Nine component props exist only to carry a
sentence, and the app uses them 124 times — `EmptyState` body ×46, `ConfirmInline`
question ×17, `Section` caption ×16, `Field` hint ×15, `PageTitle` subtitle ×11,
`SettingsRow` description ×9, `CreatePanel` hint ×4, `Callout` body ×4, `Disclosure`
hint ×2 — on top of 86 hand-written grey `<p>` sentences in 55 files. As long as the
props exist, the sentences come back.

**Width has one root cause.** `inputClasses` in `ui/field.tsx` sets `w-full`, so
every text field (75 call sites), every `Select` trigger (22, its own `w-full`) and
every `DateField` (16) fills whatever box it is in, and `FilterBar`'s search takes
`flex-1` of the row. Measured at 1440px:

## The twenty worst

1. **Every field is full width** — `inputClasses` `w-full`, `Select` `w-full`,
   `DateField` via `inputClasses`, `FilterBar` search `flex-1` (S9-24…32).
2. **Search boxes run 600–1120px** on Students, Mentors, Sessions, Feedback,
   Analytics and the program page (S10-24…37).
3. **Log a session** — the daily hot path — is a 56rem form; Minutes takes half
   the card for two digits; the note is 856px with an instruction for a placeholder
   ("Optional — what you covered, and what's next"); Attendance is a 2×2 block of
   four buttons; expired/overdrawn adds a two-sentence warning and a second
   checkbox; "Log another" reloads the whole page; saving plays a synthesised beep
   (S7-2…19).
4. **Program settings** — every toggle carries one or two sentences ("The first one
   makes this a leveled program: new enrollments pick a level, and its cohorts sit
   under one."), On/Off is said three ways per row, and the mentor picker is 992px
   (S6-44…63, S10-1…13).
5. **A sentence under every issue row** — `status.explanation` is printed under
   each row on admin Home, the notifications list and both home pages (S1-2…4,
   S3-4).
6. **46 empty states explain themselves** ("Hours show up on this page once mentors
   log their meetings.", "A mentor logs each meeting once it has happened." ×3)
   (S9-2 and every slice).
7. **The access editor explains levels three times** in one popover, has two Save
   buttons for one person, and calls the same level "Admin" in one menu and "Super
   admin" in the next (S5-66…72, S8-19…31).
8. **The live interview guide** puts a 12–17-word caption on every step, a script
   paragraph on the intro, an instruction under each of three feedback boxes, and
   takes 7+ "Next" clicks for four questions (S4-8, S4-23…29).
9. **A student's page repeats itself** — email, Telegram and folder in the subtitle
   and again in Details; approval as a chip and a row; "Registered" date nobody uses
   (S5-15…19).
10. **Granting hours leaves the page** for `/allocate`, where one short form sits in
    a 896px box under two headings, while Set a task opens inline (S5-22…25).
11. **Buttons as banners** — "Set a task" (552px), "Set a task for mentors" (1120px),
    "Show all N mentors", onboarding's three primary buttons, all `w-full` on desktop
    (S5-58, S2-52, S1-64, S8-6).
12. **Four names for "what needs you"** — "Needs you", "Things to check", "Active
    issues", "to act on" — and four for planned work: Tasks / Agenda / Mentor tasks /
    Agenda item; session vs meeting on one page; "Total minutes / Minute limit / Use
    by / Due date / Deadline" (S1-53, S6-68, S5-80, S7-31).
13. **Four confirm-button treatments and two primary buttons in one header** on the
    program page (S6-13, S6-62).
14. **The shell has three ways to search** (rail field, top-bar button, ⌘K), Settings
    twice, two bug links in one menu, a collapsible rail with its own toggle, a
    density setting, three unread markers for one update, a ⌘K badge, and an
    instruction footer in the palette (S9-1, S9-62…65, S9-76…82).
15. **Decoration everywhere** — two coloured glows on every page, a gradient sheen on
    primary buttons, a hero gradient, the looping orange thread, rows that "deal in"
    on 20 lists, meters that grow on every mount, a 2.5s flash on anchors, a hover
    sweep on the wordmark (S9-56…73).
16. **Analytics shows the year twice** (heatmap and month table), a sparkline beside
    every mentor's bar, the same legend three times, a breadcrumb that repeats the
    title (S1-28…35).
17. **The changelog summarises itself** — a hero card counting the week above the
    timeline, counts twice per day, four decorations on each heading, every item
    boxed inside a box (S1-25, S1-41…46).
18. **Type has no hierarchy left** — nine type tokens 1–2px apart, 11 sizes on one
    page, and table headers in UPPERCASE while `DESIGN.md` says sentence case
    everywhere (S9-38, S9-55, S10-62).
19. **The notification bell** repeats its own badge, adds an amber "! to act on"
    pill, and five lowercase count chips (S1-38…40).
20. **A session row** is a date tile, an avatar, the name, "with" + the mentor, a
    program dot and a grey capsule round the minutes — and its edit pencil is
    invisible until you hover (S7-46…51).

## Recommended cuts

Features and sections, not sentences. Grouped so each can be approved on its own.

- **Shell** — collapsible rail and its toggle; the density setting; two of the three
  search entries (keep ⌘K and one visible field); the second Settings entry; one of
  the two bug links; the What's new corner icon and two of three unread dots; the
  ⌘K badge; the palette's instruction footer; the profile-switch shortcut hint.
- **Decoration and motion** — page glow, button sheen, hero gradient, liquid-edge
  loop, row deal-in, meter grow, `:target` flash, wordmark sweep, badge pop,
  check-draw, frosted top bar, receipt beep. (Owner sign-off rows above.)
- **Redundant sections** — changelog hero card; analytics heatmap, per-row
  sparklines, Avg/Change columns, breadcrumb; admin Home's Time used column and
  All/Over capacity tabs; bell count chips and pill; student home first-run card,
  the Agenda list and home pagination; feedback's Lowest recent / Last rated columns
  and star glyphs beside numbers; platform's read-only Organisation section;
  "Coming up" when empty; the second assign-mentor form on the program page.
- **Redundant fields and data** — contact details in a student's subtitle;
  Registered date; Approval row; the six-figure exchange line; "Due, in words";
  Status filter on Sessions; missed/extra subtotals in the Sessions header; rating
  and note on the one-tap "Yes, it happened"; KB size on a screenshot.
- **Dead code** — `HoursRing` (no callers), `StatusCallout`, `Button` size `xs`,
  `Disclosure`'s button variant, `ExpandableText lines={1}`, `--color-stripe`.
